# แผนฟีเจอร์จองคิวตรวจสุขภาพ

Spec ID: SPEC-BKG-001  
อ้างอิง: `specs/001-booking/spec.md`  
สถานะแผน: Draft v1  
วันที่: 2569-09-16

## 1. สรุปแนวทาง

- ผู้รับบริการที่ยืนยันตัวตนแล้วเลือกแพ็กเกจ วัน และช่วงเวลาตรวจสุขภาพ
- ระบบแสดงช่วงเวลาที่ว่างและจำนวนที่นั่งคงเหลือภายใน 30 วันข้างหน้า
- ระบบตรวจสอบคิวเดิมและยืนยันการจองด้วยการตัดที่นั่งอย่างสอดคล้องกัน
- ระบบออกหมายเลขคิวและแสดงผลการจองแก่ผู้รับบริการ
- การส่งข้อความยืนยันใช้คิวงานแบบ asynchronous เพื่อไม่ให้การจองรอผลจาก SMS/LINE

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Booking | booking_id, HN, package_id, appointment_date, time_slot_id, queue_number, status, created_at | FR-BKG-02, FR-BKG-04, FR-BKG-05; ไม่เก็บเลขบัตรประชาชนตาม IF-HIS-01 |
| TimeSlot/Quota (ข้อมูลจาก UC-09) | time_slot_id, date, start_time, end_time, capacity, remaining_seats | FR-BKG-01, FR-BKG-03, FR-BKG-04, ASM-01; ฟีเจอร์นี้อ่านข้อมูล ไม่จัดการตารางหรือโควตาตาม Out of scope |
| NotificationOutbox | notification_id, booking_id, channel, payload_reference, status, next_attempt_at, attempt_count | FR-BKG-04, FR-BKG-05, IF-NOT-01, NFR-REL-02; ค่า channel ต้องรอคำตอบเรื่อง SMS/LINE |
| AuditLog | audit_id, actor, accessed_at, HN, action | DOM-PDPA-01, AC-BKG-06; เก็บไม่น้อยกว่า 1 ปี |
| Patient reference | HN และข้อมูลที่จำเป็นจาก HIS ระหว่างทำรายการ | IF-IDP-01, IF-HIS-01; ค้นด้วยเลขบัตรประชาชนผ่าน HIS แต่ไม่เก็บเลขบัตรประชาชนใน Booking |

## 4. API / หน้าจอ

| รายการ | Input/Output หลัก | รองรับ |
|---|---|---|
| หน้าจอเลือกแพ็กเกจและช่วงเวลา | Input: package_id, ช่วงวันที่; Output: วัน ช่วงเวลา และจำนวนที่นั่งคงเหลือ | FR-BKG-01, FR-BKG-06 |
| `GET /booking/availability` | Input: package_id, date range; Output: รายการ TimeSlot และ remaining_seats | FR-BKG-01, FR-BKG-06 |
| `POST /booking` | Input: package_id, appointment_date, time_slot_id; Output: booking_id, queue_number หรือเหตุผลที่ปฏิเสธ | FR-BKG-02, FR-BKG-03, FR-BKG-04 |
| หน้าจอยืนยันการจอง | Input: ข้อมูลช่วงเวลาที่เลือก; Output: ข้อความสำเร็จ หมายเลขคิว หรือช่วงเวลาใกล้เคียง 3 ตัวเลือก | FR-BKG-03, FR-BKG-04 |
| หน้าจอผลการจอง | Output: หมายเลขคิว และสถานะการส่งข้อความ | FR-BKG-04, FR-BKG-05 |
| ตัวประมวลผล `NotificationOutbox` ภายใน | Input: รายการแจ้งเตือนค้างส่ง; Output: ส่งคำขอ SMS/LINE หรือกำหนด retry | IF-NOT-01, FR-BKG-05, NFR-REL-02 |

การเรียก API ที่เข้าถึงข้อมูลผู้รับบริการต้องตรวจผลจาก IDP ก่อน และเรียก HIS ตาม IF-IDP-01 และ IF-HIS-01 ทุกครั้งที่จำเป็น

## 7. ลำดับงาน

1. ยืนยันผล IDP และเตรียมการอ้างอิงผู้รับบริการจาก HIS โดยไม่เก็บเลขบัตรประชาชนใน Booking (IF-IDP-01, IF-HIS-01)
2. อ่านข้อมูลช่วงเวลาและโควตาจาก UC-09 แล้วสร้างผลการค้นหาภายใน 30 วัน (FR-BKG-01, ASM-01)
3. สร้างหน้าจอเลือกแพ็กเกจและคำนวณช่วงเวลาว่างใหม่เมื่อเปลี่ยนแพ็กเกจ (FR-BKG-06)
4. ตรวจสอบคิวที่ยังไม่ได้ใช้ของผู้รับบริการในวันเดียวกันก่อนยืนยัน (FR-BKG-02, AC-BKG-02)
5. ทำการยืนยันการจองและตัดที่นั่งของช่วงเวลาที่เลือกให้สอดคล้องกัน (FR-BKG-03, FR-BKG-04, AC-BKG-01, AC-BKG-03)
6. ออกหมายเลขคิว บันทึกการจอง และบันทึก audit log ตามเหตุการณ์ที่เข้าถึงข้อมูล (FR-BKG-04, DOM-PDPA-01)
7. สร้างคำขอแจ้งเตือนแบบ asynchronous และจัดการคิว retry (IF-NOT-01, FR-BKG-05, NFR-REL-02)
8. ทดสอบ Acceptance Criteria ทั้งหมด รวมถึง performance ที่ผู้ใช้พร้อมกัน 200 คน (AC-BKG-01 ถึง AC-BKG-06, NFR-PERF-01)

## 8. สิ่งที่ยังไม่ทำ

- Q-01 “ช่วงเวลาใกล้เคียง” นับเฉพาะวันเดียวกัน หรือรวมวันถัดไปด้วย? -> ถามพยาบาลคัดกรอง
  ส่วนการเลือกและเรียงช่วงเวลาใกล้เคียงจะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-02 หมายเลขคิวรีเซ็ตรายวัน หรือนับต่อเนื่อง? -> ถามเจ้าหน้าที่เวชระเบียน
  ส่วนกติกาการออกหมายเลขคิวจะยังไม่สร้างจนกว่าจะได้คำตอบ

นอกจากนี้ ยังไม่สร้างส่วนที่อยู่นอกขอบเขต ได้แก่ การยกเลิก/เลื่อนคิว การชำระค่าบริการ การจัดการตารางคิวและโควตา และการยืนยันตัวตน (UC-02, UC-03, UC-09, UC-13)
